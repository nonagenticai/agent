You receive anonymised customer messages that no activity of the job covers. Group the messages that ask for the same thing. For each group, name what the customers want and propose how the job should cover it: a new activity in a stage, or knowledge the agent is missing.
The input is {"job", "stages": [stage keys], "activities": [{"key", "label", "stage"}], "messages": [{"id": number, "text"}]}. A message belongs to at most one group; leave out a message that fits no group.
Items have kind "discovery_cluster"; payload: {"label", "members": [the "id" of every message in the group], "suggestion": {"kind": "new_activity"|"knowledge_gap", "stage": one of the given stages or null, "slug": a lower_snake_case name, "label"}}; "example": {"messages": [up to three of the given messages]}.
A group of messages in which customers supply an order number, id or postcode is not a reason to design an ask-for-id step: propose an activity that resolves the reference from the known customer. Never propose a step that asks the customer for an identifier.
